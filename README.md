# 매일 공부 스탬프

매일(또는 정해진 주기로) 목표를 달성했는지 캘린더에 체크하며 기록하는 웹앱입니다.
정적 파일(HTML/CSS/JS)로만 되어 있어 GitHub Pages에서 바로 동작하고, 데이터는 **Firebase Firestore**에 저장되어 어떤 기기/브라우저로 접속하든 실시간으로 같은 데이터를 공유합니다.

## 폴더 구성

- `index.html` — 로그인, 캘린더, 현황판, 설정 화면 마크업 + 서버 연결 대기 화면
- `style.css` — 전체 스타일
- `app.js` — 앱 로직 (Firestore 연동, 화면 렌더링, 이벤트 처리). ES 모듈(`type="module"`)로 로드되며, Firebase SDK를 CDN에서 직접 import합니다(별도 빌드 과정 없음).

## 데이터 저장 방식 (Firebase Firestore)

이전 버전과 달리 사용자·목표·완료 기록이 **Firestore 프로젝트(`dailystamp-b8c37`) 하나**에 저장됩니다. 따라서:

- PC에서 만든 사용자가 스마트폰, 태블릿, 다른 PC 등 어떤 기기에서 접속해도 그대로 보입니다.
- 한 사람이 목표를 체크하면 같은 계정으로 접속한 다른 기기에도 실시간으로 반영됩니다(Firestore의 실시간 리스너 사용).
- 오프라인 상태에서도 최근 데이터는 계속 보이고 조작할 수 있으며, 다시 연결되면 자동으로 서버와 동기화됩니다.

### 로그인/세션은 Firebase Authentication이 전담합니다 (로컬 저장 없음)

이 앱은 브라우저의 localStorage/sessionStorage에 "누가 로그인했는지"를 전혀 저장하지 않습니다. 대신 4자리 코드를 실제 **Firebase Authentication 이메일/비밀번호 계정**에 매핑해서 로그인합니다.

- 사용자가 만들어질 때(관리자 시드 또는 "사용자 추가") 앱이 자동으로 `{내부ID}@dailystamp.local` 형태의 합성 이메일과, 4자리 코드로부터 계산되는 비밀번호로 Firebase Auth 계정을 함께 만듭니다. 사용자는 이 이메일/비밀번호를 직접 볼 일도, 입력할 일도 없습니다 — 화면에는 여전히 4자리 코드만 입력합니다.
- 로그인 상태 유지는 Firebase Auth 자체의 세션 지속성 기능을 그대로 사용합니다. 새로고침해도 로그인이 유지되는 건 저희가 만든 코드가 아니라 Firebase SDK가 하는 일이고, "로그아웃" 버튼을 누르면 Firebase 세션 자체가 끊깁니다.
- 관리자가 "사용자 추가"로 새 계정을 만들 때는 보조 Firebase 앱 인스턴스를 잠깐 띄워서 그 안에서만 계정을 생성하기 때문에, 관리자 본인의 로그인 세션은 끊기지 않습니다.
- 코드를 변경하면 Firestore의 코드 값과 Firebase Auth 비밀번호를 함께 갱신한 뒤 자동 로그아웃되고, 새 코드로 다시 로그인해야 합니다.

### 최초 관리자 계정은 앱이 자동으로 만들지 않습니다 — Firebase 콘솔에서 직접 만드세요

이전 버전은 `app.js` 안에 관리자 코드가 `a111`이라는 문자열로 그대로 적혀 있었고, 그다음 버전은 앱이 최초 실행 시 자동으로 코드를 생성했습니다. 지금은 둘 다 하지 않습니다. 관리자 로그인 정보(이메일/비밀번호에 해당하는 값, Firestore 문서)는 앱 코드나 실행 흐름 어디에도 남지 않고, **배포한 사람이 Firebase 콘솔에서 손수 만듭니다.**

1. **원하는 관리자 코드를 하나 정합니다.** 영문/숫자 4자리(대소문자 구분 없음), 예: `a111`.
2. **Firebase 콘솔 → Authentication → Users 탭**에서 "사용자 추가"를 누르고 아래 값을 입력합니다.
   - 이메일: `admin@dailystamp.local`
   - 비밀번호: `stamp-` + 1번에서 정한 코드를 소문자로 붙인 값 (예: 코드가 `a111`이면 비밀번호는 `stamp-a111`)
   - 계정을 만들고 나면 사용자 목록에 표시되는 **사용자 UID**를 복사해둡니다. (다음 단계에 필요합니다.)
3. **Firebase 콘솔 → Firestore Database → 데이터 탭**에서 "컬렉션 시작"을 눌러 아래처럼 문서를 만듭니다.
   - 컬렉션 ID: `users`
   - 문서 ID: `admin` (반드시 이 값이어야 합니다)
   - 필드:
     - `name` (문자열): `관리자`
     - `code` (문자열): 1번에서 정한 코드 (예: `a111`)
     - `isAdmin` (불리언): `true`
     - `createdAt` (문자열): 오늘 날짜, 예 `2026-08-20`
     - `authUid` (문자열): 2번에서 복사해둔 사용자 UID
     - `authEmail` (문자열): `admin@dailystamp.local`
4. 저장 후 사이트에 접속해서 1번에서 정한 4자리 코드로 로그인하면 관리자로 접속됩니다.

이렇게 만든 뒤에는 앱의 "사용자 추가" 기능(설정 화면, 관리자 전용)으로 나머지 사용자들을 편하게 추가하면 됩니다. 그 계정들은 앱이 자동으로 Auth 계정 + Firestore 문서를 함께 만들어줍니다 — 오직 최초 관리자 한 명만 이렇게 손으로 만들면 됩니다.

이렇게 해도 "브라우저 개발자 도구로 Firestore에 직접 접근하면 다른 계정 정보를 볼 수 있다"는 근본적인 한계는 남아있습니다(아래 보안 참고사항 참고). 관리자 계정을 앱이 아니라 콘솔에서 직접 만드는 것은 "누구나 GitHub 저장소나 페이지 소스를 열어보면 관리자 코드를 바로 알 수 있는" 문제, 그리고 "관리자 정보가 앱 코드/실행 로그에 잠깐이라도 스쳐 지나가는" 상황을 없애기 위한 것이지, Firestore 자체의 접근 권한을 사용자별로 완전히 분리해주는 것은 아닙니다.

### ⚠️ 반드시 해야 하는 Firebase 콘솔 설정

앱 코드에는 이미 Firebase 프로젝트 설정값이 들어가 있지만, Firebase 콘솔에서 아래 항목들을 켜주셔야 정상 동작합니다.

1. **익명 로그인 + 이메일/비밀번호 로그인 둘 다 사용 설정**: [Firebase 콘솔](https://console.firebase.google.com/project/dailystamp-b8c37/authentication/providers) → Authentication → Sign-in method에서 두 제공업체를 모두 켭니다.
   - **익명(Anonymous)**: 로그인 화면에 있는 동안(아직 코드를 입력하기 전) Firestore에서 사용자 목록을 읽어와 코드가 맞는지 확인하기 위한 최소한의 자격입니다.
   - **이메일/비밀번호(Email/Password)**: 실제 로그인을 처리하는 방식입니다. 이게 꺼져 있으면 코드를 입력해도 로그인이 실패합니다.
   - 익명 로그인이 꺼져 있으면 앱이 "인증에 실패했습니다" 화면에서 멈춥니다.
2. **Firestore 데이터베이스 생성 + 보안 규칙 적용**: Firebase 콘솔 → Firestore Database에서 데이터베이스를 아직 안 만들었다면 생성하고(리전은 아무거나 무방), **규칙(Rules)** 탭에 아래 내용을 붙여넣고 게시합니다.

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /{document=**} {
      allow read, write: if request.auth != null;
    }
  }
}
```

**보안 관련 중요 참고사항**: 이 규칙은 "Firebase에 익명으로라도 로그인한 사람"이면 누구든 읽고 쓸 수 있다는 뜻입니다. 4자리 코드는 앱 화면 상에서의 구분일 뿐, Firestore 자체를 사용자별로 막아주는 진짜 권한 시스템이 아닙니다(브라우저 개발자 도구 등으로 직접 Firestore에 접근하면 다른 사람 데이터도 읽고 쓸 수 있는 구조입니다). 가족·소규모 스터디 그룹처럼 신뢰할 수 있는 사람들끼리 쓰는 용도로는 충분하지만, 불특정 다수에게 공개하는 서비스로는 추가 보안(Firebase Authentication의 실제 로그인, 사용자별 문서 권한 규칙 등)이 필요합니다. 필요하시면 이 부분도 강화해드릴 수 있습니다.

## 기능 요약

1. **로그인**: 4자리 코드(영문+숫자 혼합 가능)로 사용자를 구분합니다. 최초 관리자 계정은 앱이 자동으로 만들지 않으며, 배포한 사람이 Firebase 콘솔에서 직접 만들어야 합니다(위 "최초 관리자 계정은 앱이 자동으로 만들지 않습니다" 항목 참고).
2. **내비게이션(반응형)**: 화면 폭에 따라 위치와 크기가 바뀝니다. 휴대폰처럼 좁은 화면(767px 이하)에서는 하단 탭 바로, 태블릿·데스크톱(768px 이상)에서는 좌측 사이드바로 표시되며, 화면이 넓어질수록 아이콘·글자 크기도 함께 커집니다(태블릿에서 한 단계, 1024px 이상 데스크톱에서 아이콘+글자가 나란히 붙는 넓은 사이드바로 한 단계 더). 모달(팝업)도 휴대폰에서는 화면 하단에서 올라오는 바텀시트로, 태블릿 이상에서는 화면 중앙 카드로 뜹니다. 캘린더도 화면이 넓어질수록 날짜 칸 간격·숫자·이번 달 달성률 카드 글자가 단계적으로 커집니다.
3. **캘린더(메인 화면)**: 상단에 "이번 달 내 달성률" 카드(달성률 %, 완료한 목표 수, 연속 달성일)가 표시됩니다. 아래에는 월 단위 캘린더가 표시되며, 날짜를 클릭하면 그 날짜에 해당하는 목표 목록이 열립니다. 체크 후 "완료 저장"을 누르면 기록됩니다. 완료된 날은 초록색으로, 일부만 완료된 날은 주황 점으로 표시됩니다.
4. **현황판**: 관리자를 제외한 모든 참여자의 이름, 월별 달성률(월 이동 가능), 연속 목표 달성일수를 한 화면에서 확인할 수 있습니다(관리자는 운영 계정이라 참여자 목록에 표시되지 않습니다). 목표(또는 계정)가 해당 월 중간에 생성됐다면 그 생성일부터의 날짜만 달성률 계산에 포함됩니다(그 이전 날짜는 분모에서 자동 제외).
5. **설정 화면**: 좌측 내비게이션의 "⚙️ 설정" 메뉴로 이동합니다.
   - **목표 추가**: 매일 / 주간(요일 선택) / 사용자 지정 주기(N일마다) 중 선택하고, 제목·설명과 "필수 목표 여부"를 입력해 저장합니다. 목표를 다시 눌러 수정·삭제할 수 있습니다.
   - **접속 코드 변경 (관리자 전용)**: 이제 일반 참여자는 스스로 접속 코드를 바꿀 수 없습니다. "계정" 항목에는 "접속 코드 변경" 버튼 대신 "접속 코드 변경은 관리자만 할 수 있습니다. 코드를 바꾸고 싶다면 관리자에게 요청해주세요."라는 안내만 표시됩니다. 관리자(최초 관리자·나중에 지정된 관리자 모두)는 이 항목에서 자기 자신의 코드를 바꿀 수 있고 — 바꾸면 즉시 자동 로그아웃되며 새 코드로 다시 접속해야 합니다 — 아래 "사용자 관리" 목록의 "코드 변경" 버튼으로 다른 사용자의 코드도 대신 바꿔줄 수 있습니다(이 경우 관리자 본인은 로그아웃되지 않고, 코드가 바뀐 그 사용자만 다음 로그인부터 새 코드를 써야 합니다). 두 경우 모두 이미 다른 사람이 쓰고 있는 코드는 입력하는 즉시(제출 전에도) "이미 사용 중인 코드입니다" 안내가 뜨고, 그대로 제출해도 저장되지 않습니다. 원래 쓰던 코드를 다시 입력하는 것은 중복으로 취급하지 않습니다.
   - **데이터 백업 및 복구**: 내 목표와 완료 기록을 JSON 파일로 다운로드하거나, 저장해둔 파일을 업로드해 복구할 수 있습니다. 복구 시 현재 로그인된 계정의 기존 목표·기록은 백업 파일 내용으로 모두 대체되며, 진행 전 확인 메시지가 표시됩니다. (다른 사람의 데이터가 아닌, 로그인한 본인 계정 데이터만 백업/복구합니다.)
   - **사용자 추가 (관리자 전용)**: 이름과 임시 접속 코드(자동생성 가능)를 입력해 새 사용자를 만듭니다. 새로 발급된 코드는 해당 사용자가 로그인 후 설정에서 직접 변경할 수 있습니다. "자동생성" 버튼은 이미 사용 중인 코드와 겹치지 않는 코드를 만들어주고(혹시 겹치더라도 자동으로 다시 뽑습니다), 직접 코드를 입력하는 경우에도 이미 사용 중인 코드라면 입력 즉시 안내가 뜨고 그 코드로는 추가할 수 없습니다.
   - **사용자 삭제 (관리자 전용)**: 사용자 목록에서 각 사용자 옆의 "삭제" 버튼으로 지울 수 있습니다(확인 팝업 후 진행). 그 사용자의 목표·완료 기록이 함께 삭제되고, 가능하면 Firebase Authentication 계정도 함께 지웁니다(관리자가 이미 알고 있는 그 사용자의 코드로 잠깐 로그인해 스스로를 지우는 방식이라, 클라이언트 전용 앱이라도 흔적 없이 지울 수 있습니다). 관리자 자기 자신은 목록에서 삭제 버튼이 뜨지 않습니다 — 계정을 없애려면 다른 관리자가 지워줘야 합니다. 삭제된 사람이 다른 기기에서 이미 로그인해 있던 상태였다면, 그 기기는 자동으로 로그아웃되고 로그인 화면으로 돌아갑니다.
   - **관리자 권한 지정/해제 (최초 관리자 전용)**: Firebase 콘솔에서 손으로 만든 최초 관리자(로그인 코드로 접속한 계정의 문서 ID가 `admin`인 경우)에게만, 사용자 목록의 "삭제" 버튼 옆에 "관리자" 체크박스가 보입니다. 체크하면(확인 팝업 후) 그 사용자에게 관리자 권한이 부여되어 "관리자" 배지가 즉시 표시되고, 체크를 해제하면 권한을 뺏을 수 있습니다. 팝업에서 취소하면 체크박스는 원래 상태로 되돌아갑니다. 최초 관리자 자기 자신의 행에는 이 체크박스가 뜨지 않습니다 — 실수로 스스로 권한을 해제해 관리자가 0명이 되는 상황을 방지하기 위함입니다. 관리자로 지정된 사용자는 곧바로 현황판에서도 제외되고, 해제되면 다시 나타납니다.
   - **관리자 권한의 두 등급**: 최초 관리자(문서 ID `admin`)만 다른 사용자에게 관리자 권한을 주거나 뺏을 수 있습니다. 최초 관리자가 나중에 "관리자로 지정"한 사람은 관리자 화면에 접근해 **사용자 추가/삭제**는 할 수 있지만, "관리자" 체크박스 자체가 보이지 않아 다른 사람에게 관리자 권한을 주거나 뺏을 수는 없습니다.

## GitHub Pages로 배포하는 방법

1. GitHub에서 새 저장소를 만듭니다. (예: `daily-study-stamp`)
2. 이 폴더의 `index.html`, `style.css`, `app.js` 파일을 저장소 루트에 올리고(업로드 또는 git push) 커밋합니다.
   ```bash
   git init
   git add index.html style.css app.js README.md
   git commit -m "매일 공부 스탬프 초기 배포"
   git branch -M main
   git remote add origin https://github.com/사용자명/daily-study-stamp.git
   git push -u origin main
   ```
3. GitHub 저장소의 **Settings → Pages**로 이동합니다.
4. **Source**를 `Deploy from a branch`로 두고, Branch는 `main`(또는 `master`), 폴더는 `/ (root)`를 선택 후 저장합니다.
5. 잠시 후 `https://사용자명.github.io/daily-study-stamp/` 주소로 접속하면 사이트가 열립니다.

## 참고 / 향후 개선 아이디어

- 목표의 "주간" 주기는 특정 요일(예: 월/수/금)을 선택하는 방식이고, "사용자 지정 주기"는 목표를 만든 날짜를 기준으로 N일마다 반복되는 방식입니다.
- 달성률은 "해당 기간 동안 체크했어야 할 목표 수 대비 실제로 체크한 목표 수"로 계산합니다. 미래 날짜와 목표가 하나도 없던 날(계정/목표 생성 이전 등)은 계산에서 제외됩니다.
- 연속 달성일(스트릭)은 오늘부터 거슬러 올라가며 그날의 모든 목표를 완료한 날의 연속 개수를 셉니다. 단, 오늘(또는 목표가 있는 가장 최근 날)이 아직 미완료여도 스트릭이 끊기지는 않고, 그 전날부터 판단합니다.
- 설정 화면의 "데이터 백업 및 복구"는 이제 Firestore에 저장된 내 목표·기록을 JSON으로 내보내거나, 그 파일로 Firestore의 내 데이터를 되돌리는 기능입니다(로컬 브라우저 저장소가 아니라 클라우드 데이터를 대상으로 동작합니다).
- Firestore 문서 구조: `users/{userId}`(이름·코드·관리자 여부 + 로그인용 `authUid`/`authEmail`, 관리자는 문서 ID가 항상 `admin`), `goals/{goalId}`(목표, `userId` 필드로 소유자 표시), `completions/{userId}__{goalId}__{date}`(그 날짜에 그 목표를 완료했는지, 문서 ID를 조합해 중복 없이 덮어쓰기).
- 사용량은 가족/소규모 그룹 기준으로는 Firebase 무료(Spark) 요금제 한도 안에서 충분히 여유롭게 사용할 수 있습니다.
